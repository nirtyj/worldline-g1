## 1. P1 wl-isaac

### 1.1 Launch

```bash
source /etc/profile.d/ludo.sh
cd /work/worldline-g1
/work/envs/isaaclab/bin/python -m sim_isaac.app \
    --house <id|empty> --physics-hz 200 --dds-domain 0 --dds-iface lo \
    --camera 640x480 --camera-hz 30 --rt-pace --physx-device cpu \
    [--port-offset 0] [--spawn x,y,yaw] [--stats-out <json>] [--duration <s>]
```

- Headless, `--enable_cameras` is added automatically when `--camera` is not `none`.
- Readiness: P1 prints the line `WL_ISAAC_READY {json}` to stdout and answers `ping` on REP. The band is **on** at
  that point and lowstate is flowing.
- The G1 asset is built once with `python -m sim_isaac.g1_asset --build` into `/work/worldline-g1/assets/g1/`.

### 1.2 Robot model (training parity)

- URDF: SONIC's training `gear_sonic/data/assets/robot_description/urdf/g1/main.urdf` with the 14 Dex3 hand joints
  switched from `fixed` to `revolute` (limits/axes from `gear_sonic/data/robot_model/model_data/g1/g1_29dof_with_hand.urdf`),
  converted with Isaac Lab `UrdfConverter` (`fix_base=False`, `merge_fixed_joints=True`,
  `replace_cylinders_with_capsules=True`, drive gains 0), exactly like `robots/g1.py:199-222`.
- Actuators: the `actuators` dict of `G1_CYLINDER_MODEL_12_DEX_CFG` (`gear_sonic/envs/manager_env/robots/g1.py:238-357`),
  imported, not copied: implicit PD, armature, `effort_limit_sim`, `velocity_limit_sim` per joint group. Dex3 joints
  get an extra implicit group (armature 0.01 like the MuJoCo `finger_motor` class, `g1_29dof_with_hand.xml:20-22`;
  effort/velocity limits from the URDF).
- Articulation root: self-collisions on, solver 8 position / 4 velocity iterations (`g1.py:214-218`).
- Physics: dt = 0.005 s (200 Hz) (`config/manager_env/base_env.yaml:32`; MuJoCo `SIMULATE_DT`
  `g1_29dof_sonic_model12.yaml:22`). Ground friction static = dynamic = 1.0, combine `multiply`
  (`modular_tracking_env_cfg.py:319-330`).
- PD: default `--pd implicit`: the lowcmd `kp`/`kd` are written into the PhysX drive (only when they change by >1%),
  `q`/`dq` become drive targets, `tau` is a feed-forward actuation force. The deploy's `kps`/`kds` equal the training
  stiffness/damping (`gear_sonic_deploy/.../policy_parameters.hpp:143-208` vs `g1.py:15-26`), so this is training
  parity. `--pd explicit` computes `tau + kp(q*-q) + kd(dq*-dq)` at 200 Hz and clips to the effort limit, exactly
  like MuJoCo `base_sim.py:258-288,423`.
- Before the first `rt/lowcmd` arrives the joints hold the default standing pose with the training gains (MuJoCo
  applies zero torque instead; this is a deliberate, documented deviation so the robot does not flop on the band).
  After the first lowcmd, the last received lowcmd is applied every physics step (MuJoCo semantics: it is never
  timed out).

### 1.3 DDS (unitree_sdk2py + cyclonedds 0.10.2, `unitree_hg` IDL, same as the real G1 and the MuJoCo bridge)

P1 mirrors `gear_sonic/utils/mujoco_sim/unitree_sdk2py_bridge.py` + `base_sim.py`:

| Topic | Dir | Type | Content |
|---|---|---|---|
| `rt/lowstate` | PUB, every physics step (200 Hz) | `unitree_hg LowState_` | `motor_state[0..28].{q,dq,ddq,tau_est}` in Unitree motor order; `imu_state.quaternion` = pelvis orientation **wxyz** in world; `gyroscope` = pelvis angular velocity in the **pelvis frame**; `accelerometer` = pelvis linear acceleration in **world frame, gravity not included** (MuJoCo `qacc[:3]`, bridge `:185-194`); `tick = int(t_sim*1000)` (`:202`); `mode_machine` = `--mode-machine` (default 0: the MuJoCo bridge never sets it); `crc` computed with `unitree_sdk2py.utils.crc.CRC` when `--crc` (default on; the deploy in sim runs with `--disable-crc-check` anyway, `deploy.sh:405`) |
| `rt/secondary_imu` | PUB, 200 Hz | `unitree_hg IMUState_` | `quaternion` = torso_link orientation wxyz in world; `gyroscope` = torso_link angular velocity in the **torso frame** (bridge `:196-197`, `base_sim.py:359-371`). The deploy refuses to run without it |
| `rt/odostate` | PUB, 200 Hz | `unitree_hg OdoState_` | `position`, `linear_velocity` (world), `orientation` (**wxyz**, as the MuJoCo bridge writes it despite the IDL comment), `angular_velocity` (pelvis frame) |
| `rt/dex3/left/state`, `rt/dex3/right/state` | PUB, 200 Hz | `unitree_hg HandState_` | `motor_state[0..6].{q,dq}` in Dex3 order |
| `rt/lowcmd` | SUB | `unitree_hg LowCmd_` | `motor_cmd[0..28].{q,dq,kp,kd,tau}` applied every physics step |
| `rt/dex3/left/cmd`, `rt/dex3/right/cmd` | SUB | `unitree_hg HandCmd_` | `motor_cmd[0..6].{q,dq,kp,kd,tau}` |

Motor order (hardware = MuJoCo order, `robot_parameters.hpp:90-130`, `g1_29dof_sonic_model12.yaml:119-148`):
legs 0-11 (`left_hip_pitch, left_hip_roll, left_hip_yaw, left_knee, left_ankle_pitch, left_ankle_roll`, then right),
waist 12-14 (`yaw, roll, pitch`), left arm 15-21 (`shoulder_pitch, shoulder_roll, shoulder_yaw, elbow, wrist_roll,
wrist_pitch, wrist_yaw`), right arm 22-28. Dex3 order per hand (MJCF joint order, used by the MuJoCo bridge
`base_sim.py:228-240`): `thumb_0, thumb_1, thumb_2, middle_0, middle_1, index_0, index_1`.
Isaac joints are mapped **by name**, never by index.

Lowstate heartbeat: if physics does not publish a lowstate for `--heartbeat-ms` (default 50 ms; e.g. a render hitch),
a background thread re-publishes the last one so the deploy's 500 ms `LOW_STATE_ABSENT_THRESHOLD`
(`g1_deploy_onnx_ref.cpp:299,2797-2812`) never fires on a hitch. Heartbeat re-publishes are counted in `get_stats`.

### 1.4 Camera (PUB 5565, gear_sonic sensor_server format)

- Mount: `torso_link` at the `d435_link` offset `xyz=(0.0576235, 0.01753, 0.41987)`, `rpy=(0, 0.8307767, 0)`
  (`g1_29dof_with_hand.urdf:614-619`). `main.urdf` has no `d435_link`, so the camera prim is a child of
  `torso_link` with that local transform.
- 640x480, pinhole, vertical FOV 45 deg (MuJoCo `head_camera` default `fovy`), square pixels (HFOV 57.8 deg),
  clipping 0.05-50 m. Default 30 Hz of **sim time** (`IMAGE_DT = 0.0333`, `base_sim.py:70`).
- Wire format, byte-compatible with `gear_sonic/utils/mujoco_sim/image_publish_utils.py:165-185` +
  `sensor_server.py:57-77`: one ZMQ frame = `msgpack.packb(d, use_bin_type=True)` with
  `d = {"timestamps": {"ego_view": <wall time.time()>}, "images": {"ego_view": <b64 str>}, "ego_view": <b64 str>}`,
  where `<b64 str>` = `base64(cv2.imencode(".jpg", rgb_uint8_HxWx3, [IMWRITE_JPEG_QUALITY, 80]))`.
  Like MuJoCo, the RGB array is handed to `cv2.imencode` unchanged, so `ImageUtils.decode_image` (cv2.imdecode)
  returns an **RGB** array, which is what `run_vla_inference.py:236` consumes.
- Extra (not in the MuJoCo format, ignored by gear_sonic consumers): `"t_sim"` float and `"seq"` int.

### 1.5 PUB 5601 (ground truth stream)

Multipart `[topic, msgpack(payload)]`. Subscribe with `setsockopt(zmq.SUBSCRIBE, b"gt.pose")`.

`gt.pose` at 50 Hz of sim time (every 4th physics step):

```
{ "seq": int, "t_sim": float, "t_wall": float, "rtf": float,          # rtf over the last ~1 s
  "base_pos": [x,y,z],            # pelvis origin, world, m
  "base_quat_wxyz": [w,x,y,z],    # pelvis orientation, world
  "base_lin_vel_w": [vx,vy,vz],   # world frame
  "base_ang_vel_w": [wx,wy,wz],   # world frame
  "yaw": float,                   # rad, CCW from world +x, wrapped to (-pi, pi]
  "pelvis_z": float,              # = base_pos[2] - floor_z
  "fallen": bool,                 # pelvis_z < 0.45 m or pelvis up-axis tilt > 60 deg
  "foot_contact": {"left": bool, "right": bool},   # ankle_roll_link net contact force > 20 N
  "band": bool,                   # elastic band engaged
  "lowcmd_age_s": float|null      # seconds since the last rt/lowcmd (null = never)
}
```

`gt.event` (sporadic): `{"t_sim", "t_wall", "event": "band"|"reset_robot"|"fallen"|"root_write", ...}`.

### 1.6 REP 5600 (control / ground truth)

Request: a JSON object (if the first byte is `{`, the reply is JSON) or a msgpack map (reply msgpack).
Every request has `"op"`. Every reply has `"ok": bool` and, on failure, `"error": str`.

| op | args | reply (besides `ok`) |
|---|---|---|
| `ping` | – | `t_sim, t_wall, pid, house_id, band, uptime_s` |
| `get_pose` | – | the latest `gt.pose` payload |
| `get_scene_info` | – | `house_id, floor_z, bounds [xmin,ymin,xmax,ymax], rooms [{id, name, type, polygon [[x,y],...]}], objects [{id, category, room_id, pos [x,y,z], aabb [[x,y,z],[x,y,z]]}], spawn {x, y, yaw}` (world frame, m, rad). For `--house empty`: no rooms/objects, bounds = the generated floor area |
| `get_occupancy` | `robot_radius` (default 0.25), `resolution` (default 0.05), `z_min` (0.10 above floor), `z_max` (1.60 above floor), `refresh` (false) | `path` (npz on the box), `resolution`, `origin [x0,y0]` (world xy of cell (row 0, col 0) **corner**), `shape [rows, cols]`, `robot_radius`, `source` (`scene` or `physx_overlap`). npz keys: `occ` (uint8, 1 = blocked, **not** inflated), `occ_inflated` (uint8, inflated by `robot_radius`), `resolution`, `origin`, `robot_radius`. Cell (r, c) covers x in [x0 + c*res, x0+(c+1)*res), y in [y0 + r*res, ...). |
| `band` | `on` (bool), `ramp_s` (float, release ramp, default 0), `z` (anchor height above floor, default 0.80) | `band` |
| `reset_robot` | `x, y, yaw`, `band` (default true) | `pose`. Teleports the root, zeroes velocities, sets joints to the default pose, engages the band at the new pose. **Always logged** and counted in `get_stats.root_writes`. Only for episode reset |
| `get_stats` | – | see below |
| `render_topdown` | `path` (png/jpg on the box), `fresh` (default false) | `path, width, height, center [x,y], meters_per_pixel, extent [xmin,ymin,xmax,ymax]` (image +x = world +x to the right, image up = world +y) |
| `get_joint_state` | – | `names` (Isaac order), `q`, `dq`, `motor_names` (Unitree order), `motor_q` |
| `record` | `on` (bool), `path` (npz, on stop) | `path, samples`. 50 Hz trace of t_sim, t_wall, base pose, motor q, lowcmd q/kp/kd targets, foot contacts, band (E4 evidence) |
| `shutdown` | – | stops the app cleanly |

`get_stats` reply: `rtf_1s, rtf_10s, rtf_total, physics_hz_1s, physics_hz_total, step_ms {mean, p50, p99, max}` (physics
step + bridge, excluding sleep), `render_ms {mean, p99, max}`, `render_hz`, `camera_pub_hz`, `lowstate_pub_hz`,
`heartbeat_pubs`, `overruns` (schedule resets), `lowcmd_rx_hz`, `lowcmd_leg_change_hz` (rate at which leg q targets
change), `lowcmd_count`, `root_writes`, `physx_device`, `pd_mode`, `t_sim`, `uptime_s`.

### 1.7 Elastic band

Port of `ElasticBand` (`unitree_sdk2py_bridge.py:366-395`): on the pelvis, force
`kp_pos*(anchor - pos) - kd_pos*vel` with `kp_pos = 10000, kd_pos = 1000`, torque `-kp_ang*rotvec - kd_ang*omega`
with `kp_ang = 1000, kd_ang = 10`, applied in the world frame every physics step. Differences from MuJoCo: the anchor
is `(x, y)` of the pelvis at engage time and `floor_z + z` (default 0.80 m), and the orientation target is upright
with the **yaw at engage time** (MuJoCo drives to yaw 0). `ramp_s > 0` scales the gains to zero linearly.

### 1.8 Scene plugin (house agent)

If `scenes/loader.py` exists, P1 calls `load_house(stage, house_id) -> HouseInfo` after creating the physics scene
and before spawning the robot. P1 reads these attributes (all optional except where noted):
`house_id`, `floor_z` (default 0), `spawn` (`(x, y, yaw)` or dict), `bounds` (`[xmin,ymin,xmax,ymax]`),
`rooms`, `objects` (lists of dicts in the `get_scene_info` shape), `occupancy_npz` (path in the npz format above),
or a method `to_scene_info()` returning the full `get_scene_info` dict. Without a loader, or with `--house empty`,
P1 spawns a 30 m x 30 m ground plane.
